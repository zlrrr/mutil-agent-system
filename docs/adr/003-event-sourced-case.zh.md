# ADR-003 — 采用事件溯源的 case 投影，而非可变记录

**状态。** accepted

**日期。** 2026-08-05

## 背景

REQ-0003 要求已完成的调查能够从日志重放，REQ-0053 要求重新生成的报告与实时报告相等。
常规做法——可变 case 记录加上一份旁路写入的审计日志——只有在每个写入方都记得写日志时才
同时满足两者。这种纪律会腐坏，而且腐坏是不可见的，直到某次审计需要那份从未被写下的日志。

控制台还需要实时推送（REQ-0064）。可变模型只能靠 diff 或单独发布来合成它——于是同一种
纪律又多了一处可能失效的地方。

## 决策

我们将把只追加事件日志作为唯一真相来源。Case 是折叠事件计算出的投影，同一个折叠函数同时
产生实时视图与重放视图。没有任何东西直接写投影字段。

## 后果

### 正面

- 重放相等性是结构性的，而不是靠测试硬凑出来的：一个函数，两个调用点。
- 实时事件流就是日志本身，因此控制台推送不需要单独的发布路径。
- 每次状态变化都可归属、有序、有时间，报告与审计轨迹可以直接消费。
- 并发被归约为"单写入方追加"，正好契合 ARC-004。

### 负面

- 读取 case 意味着折叠其事件；对长 case 而言这是重复劳动，除非把投影缓存在内存中——我们
  确实这样做了。
- 跨 case 的查询很别扭——除 case 列表外没有索引。但没有任何需求要求这类查询。
- 改变事件形态需要谨慎，因为旧事件仍必须能被折叠。事件类型按名称做版本区分。

### 中性

- 该日志同时是事件流的传输格式与文件存储的落盘格式，这消除了两处序列化面。

## 已考虑的备选方案

| 备选方案 | 它的吸引力 | 为何落选 |
|---|---|---|
| 可变记录 + 独立审计日志 | 熟悉；读路径最简单 | 两个可能静默分叉的真相来源。重放相等性沦为约定而非性质 |
| 可变记录 + 变更数据捕获 | 不改写模型也能重放 | 为了找回事件溯源天然具备的性质，反而增加了机械装置 |
| 事件溯源 + 快照 | 长 case 读取更快 | 为时过早：case 长度受 ARC-011 约束，因此折叠本身也是有界的 |

## 重新评估触发条件

出现某个 case，其事件数量使控制台路径上的折叠出现可测量的变慢；或者出现跨 case 查询的
需求。
