# ADR-008 — 承载判断的角色获得策略端口，承载测量的角色不获得

**状态。** 已接受

**日期。** 2026-08-10

## 背景

`project.md` §21.1 为九类 Agent 各指定了一个 system prompt。本项目交付了两个：analysis 与
critic 经由 `Reasoner` 端口，其余角色是确定性的 Go 代码。这个差距及其背后的理由，已记为
D34——一次未经升级请示的范围变更。

弥合这个差距，并不是简单地"给每个角色加一个提示词"。这些角色在**种类**上并不相同：

- **triage** 决定调查什么、在什么时间窗内调查。这是判断。
- **collection** 决定去看什么。而今天它什么也没决定：指标采集器向数据源要它提供的**每一条**
  序列，并全部分析。证据的选择——在本系统中它决定了首轮错误，因而也决定了质疑者要推翻什么
  ——是由**夹具**做出的，而不是由任何 Agent 做出的。
- **analysis** 与 **critic** 已经经由策略端口。
- **remediation** 产出的是从目录中取出的**类型化动作**。策略引擎只能对它能解析的东西设门，
  而 REQ-0041 禁止 Agent 自行编写 shell 与 SQL。在这里加一个自然语言环节并不增加判断，它
  只是在唯一会碰到真实系统的组件前面，加上一层无法解析的表面。
- **verification** 比较动作前后的信号取值。这是测量。一个被问及"恢复了吗"的模型可以与算术
  给出不一致的答案；而只要它**可以**，这个恢复结论就不再是证据。
- **executor** 从不推理。它只负责授权与调用。

因此，诚实的问题不是"有几个 Agent 带提示词"，而是"哪些决定属于判断"。用数量来回答，等于为
"对系统的描述"做优化，而不是为系统本身做优化。

## 决策

凡是产出**判断**的角色，都获得一个策略端口：确定性适配器为默认，模型适配器可由配置选择
——把 ARC-005 从单个端口推广为一族端口。凡是产出**测量**或**类型化动作**的角色，保持确定性，
不获得端口。

| 角色 | 产出 | 策略端口 |
|---|---|---|
| triage | 调查什么、时间窗多大 | 是——新增 |
| collection | 查哪些序列与日志词 | 是——新增 |
| analysis | 证据支持哪些签名 | 是——已有（ARC-005） |
| critic | 领先解释哪里不对 | 是——已有（ARC-005） |
| remediation | 目录中的类型化动作 | 否——REQ-0041 |
| verification | 信号是否恢复 | 否——算术 |
| executor | 授权与调用 | 否 |

每个模型适配器的输出仍是不可信的结构化数据。一个点名了数据源并不提供的序列的规划器，那一
条会被丢弃；一个什么也没返回的规划器，会回退到确定性方案——因为**一次服务商失败不得让调查
失明**。

**这一点偏离了 `project.md` §21.1，而且这次偏离是刻意的、并被明确标注的。** 与 D34 不同，
它在此被记录为一个**目标所有者可以推翻**的决定，而不是本项目悄悄了结的事。反对"九个提示词"
的理由，是关于其中两个特定角色的**安全性**论证；如果目标本身就是"为了九个提示词而九个提示
词"，那么这个论证就不成立，本 ADR 应当被取代。

## 后果

### 正面

- 采集真正成为一个**决定**。今天"第 1 轮看了什么"是夹具的性质；此后它是 Agent 的性质，而
  参考场景的首轮错误也随之变成一个策略可以做对、也可以做错的东西。
- 确定性路径被原样保留，因此 CON-010 的自主循环保住了它所需要的 ground truth，现有的每个
  测试也都保住了它的含义。
- 评测所计算的那个对照，从"有无质疑者"扩展到"每个阶段有无判断"，这是一件更锋利的量具。

### 负面

- 端口更多，意味着需要保持行为兼容的适配器更多。每一个都需要 REQ-0105 给推理器的那种契约
  待遇，否则就是重演 D35。
- 一个会规划采集的模型，也可能规划得很糟；而一个糟糕的第 1 轮，比一个良好的第 1 轮更容易
  抵达。这一点**可测量**，因此应当被测量，而不是朝任何一个方向去假定。

### 中性

- 本系统仍可被描述为"一个推理策略可插拔的多 Agent 系统"。改变的是：可插拔的那部分覆盖了
  调查过程中的多大比例。

## 已考虑的替代方案

| 替代方案 | 它的吸引力 | 为何落选 |
|---|---|---|
| 九个角色各一个提示词 | 字面吻合 `project.md`；与"AI-powered agentic"的表面一致性最高 | 会把自然语言放到策略引擎前面，并把一次恢复**测量**变成一种意见。它买到的是一个描述，付出的是审批门赖以成立的那整个安全论证 |
| 只保留推理器端口 | 改动最小；已经建好 | 会把"证据选择"这个决定留在夹具里——而它是整个流程中最有后果的选择，也是最难被辩称为"不属于 Agent 决定"的那一个 |
| 所有角色共用一个端口 | 类型更少 | 这些角色的输入与输出毫无共同之处；一个联合类型只会是一个披着接口外衣的 switch 语句 |
