# ADR-007 — 模型推理器从目录中选择，且不负责打分

**状态。** 已接受

**日期。** 2026-08-06

## 背景

ADR-002 让确定性规则引擎成为默认推理器，并承诺在同一端口背后提供一个基于模型的适配器。
真正动手做这个适配器时，就必须回答 ADR-002 推迟掉的那个问题：模型究竟能承担多少推理？

诱人的答案是"全部"——让模型读证据、返回它找到的任何解释，连同它自己的置信度分数。这正是
语言模型擅长的事，也正是那个"能处理没人预料到的故障"的版本。

但它同样会悄悄拆掉系统其余部分所依赖的四个性质。

**打分不再可审计。** REQ-0022 要求每个分数都能拆解为具名加权项、且各项之和等于总分；
控制台会把这个拆解渲染出来，好让评审者能与之争论。而模型断言的一个数字是拆不开的。来自
模型的"0.85"不是一个评审者能核查的主张，而是一个他们只能接受或拒绝的主张。

**反驳不再起作用。** 质疑规则是针对签名所声明的结构表达的：它需要什么证据
（`coverage_gap`）、什么能反驳它（`alternative_explanation`）、它的处置能否被验证
（`unverifiable_remediation`）。一条自由文本的主张什么都没声明，质疑者因此无从检验，
于是每个模型假设都会毫无阻碍地通过——这恰好把整个系统的意义反转了过来。

**处置不再可能。** 动作来自签名所声明的处置：白名单内的工具、参数取值范围、回滚方案与
验证信号。一个模型凭空造出的原因没有处置，因此即便它是对的，下游也没有任何东西能据此行动。

**不可信内容的边界变得模糊。** REQ-0044 规定：检索到的内容是数据，绝非指令。而模型输出
本身就是检索到的内容——它派生自可能由攻击者写下的日志与 runbook。让它变成一条流入报告的
自由文本主张，与让一行日志变成一个动作，属于同一类错误。

## 决策

模型推理器**从目录中选择，并把证据绑定到它的选择上**。它不发明主张，也不产出分数。

具体而言，它被要求回答两个问题：

1. 在这些已声明的签名中，哪些被当前证据支持？各自由哪些证据条目支持？
2. 哪些假设是薄弱的？为什么？什么证据能了断它？

其余一切保持确定性。分数由 `reasoner.Score` 依据模型所绑定的证据计算，使用与规则引擎
完全相同的权重。反驳、处置与验证依旧全部来自目录。

每个响应都要通过与其他任何贡献相同的校验：引用了不存在的证据标识符的假设会被丢弃，
不在目录中的签名标识符会被丢弃，落在封闭集合之外的裁决会被丢弃。编排器既有的角色检查与
贡献检查原样适用（REQ-0005、REQ-0021）。

## 后果

**这换来了什么。** 这次替换是真正发生在端口背后的：更换适配器改变的是解释如何被**选出**，
而完全不改变它们如何被打分、被挑战、被执行、被审计。端口之上的每个测试都保持其含义。
一个凭空捏造证据标识符的模型，得到的是一个被丢弃的假设，而不是报告里一条伪造的引用。

**这付出了什么代价——而且是真实的代价。** 一个成因不在目录中的故障，模型推理器无法为它
命名，只能通过新增签名来表达。这个系统不会用一个没人写下来过的解释给你惊喜。这是一次
刻意的取舍：目录正是那套让打分、反驳与处置成为可能的封闭词汇；而一个能被打分却无法被执行、
或能被执行却无法被审计的解释，在这里的价值低于一个干脆缺席的解释。

**什么会改变这个决策。** 如果目录大到"覆盖度不再是约束瓶颈"，并且出现了一种能把模型判断
拆解为可核查项的打分方案，那么上面第一条论据就会削弱。今天这两点都不成立。

**何时重新审视。** 当出现一个目录无法表达的故障样例，且把它表达为签名被证明是更难的那条路。
